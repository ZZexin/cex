# 数据列说明：哪些是测量值，哪些是计算值

本文说明本工具从蓝电 `.cex` 文件导出的每一列数据的来源。分三类：

- **A 仪器测量并直接存入文件的原始量**（本工具只做单位换算）
- **B 仪器在测试过程中计算后存入文件的量**（本工具原样读取，不重新计算）
- **C 本工具由 A/B 计算得到的量**

记号：下标 `k` 表示第 k 条记录（工步内按时间顺序），`t` 单位 s，`V` 单位 V，`I` 单位 A。

---

## A. 仪器测量、文件中直接存储的原始量

每条 16 字节记录中存的是整数原始值，本工具按下式换算成物理量：

| 导出列 | 文件中的原始字段 | 换算公式 | 说明 |
|---|---|---|---|
| `TestTime_s` | `u32` 时间计数 `n_t` | `TestTime_s = n_t × 0.01` | 累计测试时间，分辨率 10 ms。记录间隔（本例 60 s）由工步设置决定 |
| `Voltage_V` | `u16` 电压原始值 `n_V` | `Voltage_V = n_V × 0.155 × 10⁻³` | 0.155 mV / LSB（5 V 量程） |
| `Current_mA` | `i16` 电流原始值 `n_I` | `Current_mA = n_I × 0.31 × 10⁻³` | 0.31 µA / LSB（10 mA 量程）；充电为正、放电为负，静置为 0 |
| （工步）`Step` | 工步头 `u16`（去掉 0x8000 位） | 直接读取 | 对应工步设置中的工步号：1 静置、2 恒流放电、3 恒流充电 |
| （工步）`Mode` | 工步头 `u8` 模式码 | `0x70 → Rest`，`0x02 → CC_DChg`，`0x03 → CC_Chg` | 直接映射为文字 |
| （文件）开始时间 | 文件头 `u32` Unix 时间戳 | 直接读取 | 用于计算 `DateTime` |

> 两个换算系数（0.155 mV、0.31 µA）不是从文件里读到的，而是用实测数据标定的（见附录）。
> 侧栏可修改；其它量程的通道请按比例调整。

## B. 仪器计算后存入文件的量

这两列由测试仪在采样时按其内部（比记录频率高得多的）采样电流积分得到，然后以 `float32` 存入记录。本工具**只读取并换算单位，不重新积分**：

| 导出列 | 文件字段 | 换算 | 仪器内部的计算（推断并验证） |
|---|---|---|---|
| `Capacity_mAh` | `f32` 容量 (Ah) | `Capacity_mAh = Q_Ah × 1000` | `Q(t) = ∫₀ᵗ |I| dτ / 3600`，每个工步从 0 重新开始累计 |
| `Energy_mWh` | `f32` 能量 (Wh) | `Energy_mWh = E_Wh × 1000` | `E(t) = ∫₀ᵗ V·|I| dτ / 3600`，每个工步从 0 重新开始累计 |

验证方法：对恒流段做 `ΔQ/Δt`，得到的电流与 `Current_mA` 一致（偏差 < 0.1 %）；`ΔE/ΔQ` 等于相邻两点电压的平均值，说明能量按 `V·I·dt` 积分。

## C. 本工具计算的量

### C1. 逐条记录的派生列

| 导出列 | 公式 | 说明 |
|---|---|---|
| `Index` | 记录在文件中的序号，从 1 开始 | 纯计数 |
| `StepSeq` | 工步在文件中的出现顺序，从 1 开始 | 第 n 个工步头 → n。区别于 `Step`（工步号会重复，如 2,3,2,3,…） |
| `Cycle` | `Cycle₁ = 1`；此后每当 `Step_n ≤ Step_{n-1}` 时 `Cycle += 1` | 工步号不再递增（循环跳回）即视为进入下一圈。序列 1,2,3,2,3 → 圈号 1,1,1,2,2 |
| `StepTime_s` | `StepTime_s = TestTime_s − TestTime_s(本工步第一条记录)` | 工步内时间，每步从 0 开始 |
| `DateTime` | `DateTime = 开始时间戳 + TestTime_s` | 按文件中记录的时间直接相加，不做时区转换 |

### C2. 循环统计表（`*_cycles.csv`）

对每一圈 `c`，记该圈内所有放电工步集合为 `D`，充电工步集合为 `C`：

| 列 | 公式 |
|---|---|
| `DischargeCapacity_mAh` | `Q_d = Σ_{s∈D} max(Capacity_mAh 在工步 s 内)` |
| `ChargeCapacity_mAh` | `Q_c = Σ_{s∈C} max(Capacity_mAh 在工步 s 内)` |
| `CoulombicEfficiency_pct` | `CE = Q_d / Q_c × 100` （本协议先放后充，所以按放电/充电计算；若 `Q_c = 0` 为空） |
| `DischargeEnergy_mWh` | `E_d = Σ_{s∈D} max(Energy_mWh 在工步 s 内)` |
| `ChargeEnergy_mWh` | `E_c = Σ_{s∈C} max(Energy_mWh 在工步 s 内)` |
| `MeanDischargeVoltage_V` | `mean(Voltage_V)`，对该圈所有放电记录取算术平均（记录等时间间隔，故等价于时间加权平均） |
| `MeanChargeVoltage_V` | 同上，对充电记录 |
| `Start` | 该圈第一条记录的 `DateTime` |
| `Duration_h` | `(TestTime_s_末 − TestTime_s_首) / 3600` |

因为每个工步的容量从 0 累计，工步内最大值即该工步的总容量；一圈内若有多个同类工步则求和。

### C3. CSV → CEX 时的反向计算

| 目标字段 | 公式 |
|---|---|
| 时间计数 | `n_t = round(TestTime_s / 0.01)` |
| 电压原始值 | `n_V = round(Voltage_V / 0.155e-3)`，截断到 0…65535 |
| 电流原始值 | `n_I = round(Current_A / 0.31e-6)`，截断到 −32768…32767 |
| 工步划分 | 若 CSV 有 `StepSeq`/`Step` 列按其变化分段；否则按电流符号：`I > 2 % · max|I|` 充电，`I < −2 % · max|I|` 放电，其余静置 |
| 容量 (Ah) | CSV 有容量列：`Q_k = |Q_k − Q_首|`（每步归零）；否则梯形积分 `Q_k = Σ_{j≤k} ½(|I_j| + |I_{j-1}|)(t_j − t_{j-1}) / 3600` |
| 能量 (Wh) | CSV 有能量列：`E_k = |E_k − E_首|`；否则 `E_k = Σ_{j≤k} ½(V_j|I_j| + V_{j-1}|I_{j-1}|)(t_j − t_{j-1}) / 3600` |
| 工步开始时间戳 | `ts = 开始时间戳 + round(TestTime_s_首)` |
| 静置步 | 容量、能量写 0 |
| 校验和 | 文件头、信息块、工步块各一个：对应字节区间内所有小端 `u16` 的和（取低 32 位） |

## 附录：换算系数是怎么标定的

文件里没有找到明确的量程/系数字段，两个系数由数据本身反推，三种方法结果一致（差异 < 0.05 %）：

1. **截止电压法**：充电步末条记录 `n_V ≈ 11 613 ~ 11 616` 对应设定的 1.8 V 截止，放电步末条 `n_V ≈ 5 150 ~ 5 160` 对应 0.8 V →
   `k_V ∈ [1.8/11616, 0.8/5150] ≈ 1.550 × 10⁻⁴ V`。
2. **能量/容量法**：`ΔE_k / ΔQ_k = V̄_k = k_V · (n_{V,k} + n_{V,k−1}) / 2`，对全部恒流记录做最小二乘 → `k_V = 1.5500 × 10⁻⁴ V`。
3. **容量/电流法**：`ΔQ_k / Δt_k = k_I · n_{I,k}`（Δt = 60 s）→ `k_I = 3.100 × 10⁻⁷ A = 0.31 µA`；与工步设置中的 0.04 mA（`n_I ≈ 128 ~ 129`）一致。

即 `k_V = 0.155 mV`（≈ 5.08 V / 32768），`k_I = 0.31 µA`（≈ 10.16 mA / 32768）。
