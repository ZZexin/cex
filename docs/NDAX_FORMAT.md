# 新威 NDAX 解码

当前支持已验证的 **NDC v5 / filetype 1、单个 data.ndc** 格式。
NDAX 是 ZIP 容器；本工具直接在内存读取并检查 ZIP CRC，不需要新威软件，也不把附件解压到磁盘。
其它 NDC 版本或未知电流量程会明确报错，不能套用 CEX 的量程系数。

## 容器内容

| 文件 | 用途 |
|---|---|
| `data.ndc` | 主通道测量记录 |
| `Step.xml` | 工步配置，包含充放电电流、截止电压、采样间隔和循环控制 |
| `Step1.xml`、`Step2.xml` 等 | 工步配置修改历史；不能用最后的设置覆盖早期测量值 |
| `TestInfo.xml`、`TestInfo1.xml` 等 | 设备、单元、通道、测试起止时间和修改计数 |
| `VersionInfo.xml` | BTS 客户端、服务端及硬件版本 |
| `data_log.ndc` | 运行日志，不作为测量记录解析 |
| `DAComment.xml` | 软件中的注释 |

XML 按声明编码读取（UTF-8 或 GB2312/GBK 兼容编码），不执行其中的内容。

## data.ndc 二进制结构

文件开头第 0 字节是类型（本例 1），第 2 字节是版本（本例 5）。
前 4096 字节为文件头，后续按 4096 字节分页。
每个数据页内偏移 125 至 4039 是 45 条 87 字节记录。
有效测量记录的第 7 字节是 `0x55`，尾页未使用的位置为填充。

下面偏移均相对于一条 87 字节记录，整数为小端：

| 偏移 | 类型 | 含义 / 换算 |
|---:|---|---|
| 8 | uint32 | 记录序号 Index |
| 12 | uint32 | 仪器循环计数 CycleRaw，从 0 开始 |
| 16 | uint8 | 工步号 Step |
| 17 | uint8 | 状态码：1 恒流充电，2 恒流放电，4 静置等 |
| 23 | uint64 | 工步累计时间，除以 1000 得秒 |
| 31 | int32 | 电压，除以 10000 得 V |
| 35 | int32 | 电流，乘该条记录的量程系数得 mA |
| 43 / 51 | int64 / int64 | 充电 / 放电容量，乘量程系数再除以 3600 得 mAh |
| 59 / 67 | int64 / int64 | 充电 / 放电能量，乘量程系数再除以 3600 得 mWh |
| 75 | uint16 + 5×uint8 | 年、月、日、时、分、秒，本地日历时间 |
| 82 | int32 | 本条记录的电流量程码 |

用户提供的两份样本都使用记录量程码 **−1**，换算系数是 **0.00001 mA / count**。
例如电流整数 `4507` 对应 `0.04507 mA`，`−899` 对应 `−0.00899 mA`。
不能拿 TestInfo 中的最大量程替代每条记录的量程。

## 数据、循环与调整

测量 CSV 使用与 CEX 页相同的主列：`Index, Cycle, Step, StepSeq, Mode, TestTime_s,
StepTime_s, Voltage_V, Current_mA, Capacity_mAh, Energy_mWh, DateTime`。
另保留 `CycleRaw`、`RangeCode` 和 `StatusCode`，便于核对来源。
`Mode` 保留 CC、CV、CCCV 等具体状态，循环汇总按充/放电方向合并工步。
主曲线为 **Voltage (V) vs Specific capacity (mAh/cm²)**。每个文件可输入电极面积，默认 **0.18 cm²**，
横轴为调整后的 `Capacity_mAh / 面积`。数据 CSV 同时保留容量并增加
`ElectrodeArea_cm2`、`SpecificCapacity_mAh_cm2`；更改面积只改变面积归一化结果。
`Capacity_mAh` 和 `Energy_mWh` 分别取当前工步方向对应的容量、能量计数，首次读取不重新积分。

- **工步序号**：按工步号、仪器循环计数、状态变化或工步计时回退划分；它不同于反复使用的工步号。
- **累计测试时间**：前面工步的累计时长之和 + 当前工步时间；不包含暂停间隙。
- **绝对时间**：保留文件里的日历时间，不从累计测试时间重建，不进行时区平移。
- **循环分组**：默认 `CycleRaw + 1`；可选按充电或放电开始新圈，以便匹配 BTSDA 的统计设置。
- **循环容量**：同圈同方向的各工步最大累计容量之和。
- **库仑效率**：同圈放电容量 / 充电容量 × 100%，缺少一侧容量时为空。
- **调整**：先对每圈充、放电容量分别应用百分比和 mAh offset，再应用效率百分比和百分点 offset。
  同方向工步按原容量占比分配目标容量，电流与能量同步反算；原附件不被覆盖。
  图表、预览、单个 CSV 和批量 ZIP 均使用调整后的数据。
- **末圈**：保留实际记录；若末工步还没达到设置的电压截止条件，显示提示，不凭空补全数据。

## 平台曲线模拟

“电压–面积比容量”页右侧可开启平台模拟，选择充电、放电或两者；仅作用于当前选中的循环。
以调整前面积比容量的 `[a,b]` 区间为平台，长度比例为 `s`：横坐标映射为
`q' = q + (s-1) × clip(q-a, 0, b-a)`。区间前不变，区间内拉伸/压缩，区间后连续平移。
区间是手动指定的容量范围，不自动判断电压平台；每个工步使用自身累计容量。
电压 offset 仅作用于该区间，可设置两端平滑过渡宽度（区间长度的百分比）。

平台拉伸保持采样时间和日期不变，以 `I_i = ±3600 × (Q_i-Q_(i-1)) / Δt_i` 反算
每个采样区间的等效电流，写入 `Current_mA` 并以
`CurrentRepresentation=interval_equivalent_right_endpoint` 标识；这不是原仪器瞬时电流。
能量按调整后电压对容量的梯形积分更新。仅电压 offset 不改变容量或电流。

独立横移只修改 `PlotSpecificCapacity_mAh_cm2`，不改变 `Capacity_mAh`、
`SpecificCapacity_mAh_cm2=Capacity_mAh/面积`、电流和循环容量；允许显示坐标为负。
实际选中记录的 offset 保存在 `ProfileXOffset_mAh_cm2`。

所有操作从每次运行的基线重新计算，不累计叠加；顺序为循环统计调整 → 平台模拟 → 显示横移。
灰色对照曲线为上传文件的原始测量（不包含循环统计调整）。模拟 CSV 使用 `_simulated` 文件名，
`DataKind=profile_simulation`，包含 `Original_*` 原始测量列、`Baseline_*` 平台调整前列和平台参数。
预览、循环统计、单文件 CSV 和批量 ZIP 使用相同结果。原始 NDAX 不修改；这些结果是人为设定的
what-if 模拟，不是倍率校正、光电流测量或新的实验结果。

曲线下方可切换查看电压、电流、容量、能量、面积比容量和横轴显示坐标的原始值、调整后值、
变化量与变化率。CSV 的 `Delta_* = 调整后 - Original_*`，
`ChangePct_* = Delta_* / abs(Original_*) × 100`，原始值为零时变化率留空。
纯横移的 `Delta_SpecificCapacity_mAh_cm2` 为零，变化体现在 `Delta_PlotSpecificCapacity_mAh_cm2`。
循环统计 CSV 另列原始充放电容量、CE 及其差值（CE 差值为百分点）。

## 写回边界

本页当前支持 NDAX 解码、分析、调整和 CSV 导出，**不提供 CSV → NDAX 或修改后 NDAX 下载**。
可靠写回还需要验证 NDC 页头/索引、运行日志、配置历史以及 BTSDA 的实际读取行为。
ZIP 重新打包成功或用同一个解析器回读成功，都不足以证明原厂软件兼容性。

二进制布局与量程表核对来源：[NewareNDA 上游项目](https://github.com/d-cogswell/NewareNDA)，
重点参考其 `NewareNDAx.py`、`dicts.py`。本项目实现为面向上述布局的内存解析器，运行时不依赖该包。
